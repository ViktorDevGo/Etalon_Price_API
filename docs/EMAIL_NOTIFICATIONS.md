# Email уведомления о синхронизации

## Обзор

Система автоматически отправляет email уведомления после каждой синхронизации номенклатуры.

**Что отправляется:**
- Тип номенклатуры (шины/диски)
- Количество добавленных записей
- Количество пропущенных дублей
- Общее количество записей в БД
- Время выполнения и детали синхронизации

**Кому отправляется:** v.boyarkin@etalon-shina.ru
**От кого:** admin@etalon-shina.ru

## Настройка

### 1. Конфигурация (.env)

```env
# Email Configuration
EMAIL_ENABLED=true
EMAIL_SMTP_HOST=mail.hosting.reg.ru
EMAIL_SMTP_PORT=587
EMAIL_USERNAME=admin@etalon-shina.ru
EMAIL_PASSWORD=S69Y1ypojVLCZHO8
EMAIL_FROM=admin@etalon-shina.ru
EMAIL_NOTIFICATION_TO=v.boyarkin@etalon-shina.ru
```

**Доступные порты:**
- `587` - SMTP с STARTTLS (рекомендуется)
- `465` - SMTP с SSL/TLS
- `25` - обычный SMTP (не рекомендуется)

### 2. Тестирование

Перед использованием в продакшене проверьте отправку тестового письма:

```bash
go run cmd/test-email/main.go
```

**Ожидаемый результат:**
```
✅ Test email sent successfully!
```

## Использование

### Автоматическая отправка при синхронизации

Email отправляется автоматически после каждой синхронизации:

```bash
# Синхронизация шин (отправит 1 письмо)
go run cmd/sync-nomenclature/main.go -type=tyres

# Синхронизация дисков (отправит 1 письмо)
go run cmd/sync-nomenclature/main.go -type=rims

# Полная синхронизация (отправит 2 письма: для шин и дисков)
go run cmd/sync-nomenclature/main.go -type=all
```

### Отключение уведомлений

Временно отключить email уведомления:

```env
EMAIL_ENABLED=false
```

## Troubleshooting

### Проблема: "Connection reset by peer"

**Причины:**
1. Неправильные учетные данные
2. IP адрес не в whitelist
3. Проблемы с TLS/SSL
4. Firewall блокирует подключение

**Решения:**

#### 1. Проверить учетные данные

Убедитесь что EMAIL_USERNAME и EMAIL_PASSWORD верны:
```bash
# Проверить настройки в .env
grep EMAIL .env
```

#### 2. Добавить IP в whitelist

Узнать внешний IP сервера:
```bash
curl -4 ifconfig.me
# или
curl -4 icanhazip.com
```

Добавить этот IP в whitelist SMTP сервера через панель управления хостингом reg.ru:
- Войти в панель управления
- Настройки почты → Безопасность
- Добавить IP адрес сервера

#### 3. Попробовать другой порт

В `.env` измените порт:
```env
EMAIL_SMTP_PORT=465  # для SSL/TLS
# или
EMAIL_SMTP_PORT=587  # для STARTTLS (рекомендуется)
```

#### 4. Проверить доступность портов

```bash
# Проверить порт 587
nc -zv -w 5 mail.hosting.reg.ru 587

# Проверить порт 465
nc -zv -w 5 mail.hosting.reg.ru 465
```

#### 5. Проверить параметры подключения

Убедитесь что используете правильные настройки согласно документации хостинга:

**Исходящая почта (SMTP):**
- Сервер: `mail.hosting.reg.ru`
- Порт: `587` (STARTTLS) или `465` (SSL/TLS)
- Аутентификация: требуется
- Логин: `admin@etalon-shina.ru`
- Пароль: ваш пароль

#### 6. Тестирование через telnet/openssl

**Проверка SMTP с STARTTLS (порт 587):**
```bash
openssl s_client -starttls smtp -connect mail.hosting.reg.ru:587 -crlf
```

**Проверка SMTP с SSL/TLS (порт 465):**
```bash
openssl s_client -connect mail.hosting.reg.ru:465 -crlf
```

После подключения введите:
```
EHLO localhost
AUTH LOGIN
[base64 encoded username]
[base64 encoded password]
QUIT
```

#### 7. Обратиться в поддержку хостинга

Если ничего не помогает, обратитесь в техподдержку reg.ru:
- Email: support@reg.ru
- Телефон: 8 800 250-0-509

Предоставьте:
- IP адрес сервера
- Логин почтового ящика (admin@etalon-shina.ru)
- Ошибку: "connection reset by peer" при подключении к SMTP

### Проблема: "Email sent" но письмо не приходит

1. Проверьте папку SPAM
2. Проверьте логи на SMTP сервере
3. Проверьте правильность адреса получателя:
   ```env
   EMAIL_NOTIFICATION_TO=v.boyarkin@etalon-shina.ru
   ```

### Проблема: "TLS handshake timeout"

Увеличьте timeout в коде или используйте порт 465 с SSL вместо 587 с STARTTLS.

## Архитектура

### Файлы

```
internal/email/
├── client.go       # SMTP client
└── templates.go    # Email templates

cmd/
├── test-email/     # Тестовый скрипт отправки
└── sync-nomenclature/ # Интеграция с синхронизацией
```

### Поток работы

1. Синхронизация номенклатуры выполняется
2. Собирается статистика (SyncResult)
3. Создается email сообщение (HTML)
4. Отправляется через SMTP

### Настройки TLS

- Порт 465: Implicit SSL/TLS (d.SSL = true)
- Порт 587: STARTTLS (по умолчанию)
- TLS Config: ServerName + InsecureSkipVerify

## Безопасность

⚠️ **Важно:**
- Храните EMAIL_PASSWORD в секрете
- Используйте `.env` файл (не коммитьте в git)
- Используйте TLS/SSL для всех подключений
- Не используйте InsecureSkipVerify=true в продакшене

## Интеграция с планировщиком

Если используете cron или планировщик для автоматической синхронизации:

```bash

0 2 * * * cd /path/to/project && go run cmd/sync-nomenclature/main.go -type=all >> /var/log/sync.log 2>&1
```

Email будет отправлен автоматически после выполнения.
